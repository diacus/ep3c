#+TITLE: Shell integration: vterm, eshell
#+AUTHOR: Diacus Magnuz
#+STARTUP: overview

Configuration settings to invoke a *Shell* window. All the terminal
related key bindings live under the =SPC t= prefix: the lowercase key
opens the shell in a popup window, the uppercase one opens it in the
current window.

- =SPC= + =t= + =v= :: a new vterm buffer in a popup window (UNIX only)
- =SPC= + =t= + =V= :: a new vterm buffer in the current window (UNIX only)
- =SPC= + =t= + =s= :: shell in a popup window
- =SPC= + =t= + =S= :: shell in the current window
- =SPC= + =t= + =t= :: term in a popup window
- =SPC= + =t= + =T= :: term in the current window
- =SPC= + =t= + =e= :: eshell in a popup window
- =SPC= + =t= + =E= :: eshell in the current window
- =SPC= + =t= + =i= :: ielm in a popup window
- =SPC= + =t= + =I= :: ielm in the current window

The =SPC t p= and =SPC t P= bindings, for PowerShell, belong to the
[[file:windows.org][windows module]].

#+begin_src emacs-lisp
  (use-package popup-window
    :quelpa (popup-window :fetcher github :repo "diacus/popup.el"))
#+end_src

* Vterm
Emacs-libvterm ([[https://github.com/akermu/emacs-libvterm][vterm]]) is a fully-fleged terminal emulator inside GNU
Emacs based on [[https://github.com/neovim/libvterm][libvterm]], a C library (UNIX like systems only)
#+begin_src emacs-lisp
  (unless (member system-type '(ms-dos windows-nt cygwin))
    (defun shell--popup-vterm ()
      "Open a new vterm buffer in a popup window at the bottom of the
frame.  Multi-vterm spawns it, so the popup always starts a fresh
shell; the window closes by itself when the shell exits."
      (interactive)
      (funcall (make-repl-popup #'multi-vterm)))

    (use-package vterm
      :ensure t))
#+end_src

The [[https://github.com/suonlight/multi-vterm][multi-vterm.el]] package allows managing multiple =vterm= buffers:
it is what spawns a fresh shell on =SPC t v= and =SPC t V=.
#+begin_src emacs-lisp
  (unless (member system-type '(ms-dos windows-nt cygwin))
    (use-package multi-vterm
      :ensure t
      :after (vterm projectile)
      :config
      (evil-define-key '(normal visual) 'global
        (kbd "SPC t v") #'shell--popup-vterm
        (kbd "SPC t V") #'multi-vterm)))
#+end_src

The shell's current command line can be edited in a separate buffer,
like readline's =C-x C-e= (=edit-and-execute-command=): the text after
the prompt is opened for editing in its own frame when Emacs is
graphic.  With =C-c C-c= the edited line is placed back on the shell
prompt, without executing it; =C-c C-k= (or plain =C-x k=) discards the
edit.
#+begin_src emacs-lisp
  ;; The editor itself works for every shell: it takes the command
  ;; line text, shows it in a fresh buffer -- in its own frame when
  ;; Emacs is graphic -- and hands the edit back to the shell on
  ;; accept.  The shell specifics live in a `shell--edit-put-back'
  ;; buffer-local function.  Where the pending input actually rests
  ;; splits them in two: vterm and a char-mode term carry it in the
  ;; pty, so their edits are sent through it as readline keystrokes;
  ;; eshell and the comint buffers (M-x shell, any comint REPL) keep
  ;; it in the buffer, and their edits are buffer edits.  See the
  ;; Eshell and the term and shell editors sections below.

  (defvar shell--edit-counter 0
    "Counter to generate unique names for shell edit buffers.")

  (defvar-local shell--edit-source nil
    "The shell buffer whose command line is being edited.")

  (defvar-local shell--edit-frame nil
    "The frame `shell--edit-buffer' created for this buffer, or nil.")

  (defvar-local shell--edit-put-back nil
    "Function of \(SOURCE-BUFFER TEXT\) placing TEXT on the shell prompt.")

  (defun vterm--edit-read-line ()
    "Return the shell's current command line in this vterm buffer.
Readline's =C-a= is sent first, so the terminal cursor sits at the
start of the input, right after the prompt; the command line is
read from there to the end of the line, without depending on any
shell integration or prompt detection.  The side effect is that
the shell's cursor moves to the start of its input line."
    (vterm-send-key "a" nil nil t)
    (when vterm--process
      (accept-process-output vterm--process 0.5))
    (vterm-reset-cursor-point)
    (let ((beg (vterm--get-cursor-point))
          (end (vterm--get-end-of-line)))
      (substring-no-properties
       (buffer-substring (min beg end) (max beg end)))))

  (defun vterm--edit-put-back (source text)
    "Place TEXT on the vterm prompt of SOURCE, without executing it.
Readline's C-a C-k discards the shell's current input first — the
prompt is left with exactly the edits, ready to run with RET."
    (if (not (with-current-buffer source
               (and (bound-and-true-p vterm--term)
                    (process-live-p vterm--process))))
        (message "shell edit: the shell is gone, discarding the edit")
      (with-current-buffer source
        (vterm-send-key "a" nil nil t) ; C-a: readline, start of input
        (vterm-send-key "k" nil nil t) ; C-k: readline, kill to end
        (when (> (length text) 0)
          (vterm-insert text))
        ;; The final cursor sync races with the shell's redraw of
        ;; the cleared line; it is cosmetic here.
        (ignore-errors (vterm-reset-cursor-point)))))

  (defun shell--edit-display (buffer)
    "Display BUFFER for editing.

Pop up a fresh frame when Emacs is graphic (the usual case when
it runs as a daemon); on TTY frames fall back to the default
window display.  Return the frame that was created, or nil when
BUFFER went to a window of the current frame."
    (if (display-graphic-p)
        (let ((previous (selected-frame))
              (window (display-buffer
                       buffer
                       '((display-buffer-pop-up-frame)
                         (reusable-frames . nil)
                         (dedicated . t)))))
          (when (and (window-live-p window)
                     (not (eq (window-frame window) previous)))
            (select-frame-set-input-focus (window-frame window))
            (window-frame window)))
      (pop-to-buffer buffer)
      nil))

  (defun shell--edit-close-frame ()
    "Delete the frame created for this edit buffer, when it still shows it.
Added to `kill-buffer-hook' by `shell--edit-buffer'."
    (when (and (frame-live-p shell--edit-frame)
               (memq (current-buffer)
                     (mapcar #'window-buffer
                             (window-list shell--edit-frame 'never))))
      (delete-frame shell--edit-frame)))

  (defun shell--edit-accept ()
    "Place the edited line back on the shell prompt, without executing it.
The transfer goes through `shell--edit-put-back'; running the
command on the fresh line stays with the shell's own RET.  The
buffer is killed *before* the transfer: killing hands the window
back to the shell buffer, which redisplay remembers with an old
stale point, and the put-back -- which leaves the shell's point at
the end of its pending input, where RET sends it -- must have the
last word on that."
    (interactive)
    (let* ((source shell--edit-source)
           (put-back shell--edit-put-back)
           (text (string-trim-right
                  (buffer-substring-no-properties
                   (point-min) (point-max)))))
      (kill-buffer (current-buffer))
      (if (not (and put-back
                    (bufferp source)
                    (buffer-live-p source)))
          (message "shell edit: the shell is gone, discarding the edit")
        (funcall put-back source text))))

  (defun shell--edit-abort ()
    "Leave the shell prompt untouched and discard the edit buffer."
    (interactive)
    (kill-buffer (current-buffer)))

  (defun shell--edit-buffer (source line put-back)
    "Open a fresh buffer with LINE, the command line of the SOURCE shell.
PUT-BACK receives (SOURCE TEXT) when the edit is accepted.  The
buffer is shown in its own frame when Emacs is graphic, and there
C-c C-c accepts the edit while C-c C-k (or plain C-x k) discards
it."
    (with-current-buffer
        (generate-new-buffer
         (format "*shell edit %d*"
                 (setq shell--edit-counter (1+ shell--edit-counter))))
      (setq-local shell--edit-source source)
      (setq-local shell--edit-put-back put-back)
      (setq-local shell--edit-frame
                  (shell--edit-display (current-buffer)))
      (add-hook 'kill-buffer-hook #'shell--edit-close-frame)
      (insert line)
      (goto-char (point-max))
      (local-set-key (kbd "C-c C-c") #'shell--edit-accept)
      (local-set-key (kbd "C-c C-k") #'shell--edit-abort)
      (current-buffer)))

  (defun vterm--edit-command-line ()
    "Edit the shell's current command line in a fresh buffer.
Mirrors readline's `edit-and-execute-command': the command line
after the prompt of this vterm is copied into a temporary buffer,
shown in a new frame when Emacs is graphic.  There, C-c C-c puts
the edited text back on the prompt and C-c C-k discards it;
nothing is executed."
    (interactive)
    (unless (and (bound-and-true-p vterm--term)
                 (process-live-p vterm--process))
      (user-error "No running shell in this vterm buffer"))
    (shell--edit-buffer (current-buffer)
                        (vterm--edit-read-line)
                        #'vterm--edit-put-back))

  (with-eval-after-load 'vterm
    (define-key vterm-mode-map (kbd "C-x C-e") #'vterm--edit-command-line))
#+end_src

For =eshell=, the same command line editor is available through its
own =C-x C-e=: the line between the prompt and the end of the buffer
is opened in a fresh buffer (frame included), and =C-c C-c= leaves it
on the prompt, ready to run with =RET=.  =C-c C-k= leaves the input as
it was.  The editor refuses to edit while a command is still
running, since eshell delimits the pending input with
=eshell-last-output-end= only afterwards.
#+begin_src emacs-lisp
  (defun eshell--edit-prompting-p ()
    "Return t when this eshell buffer is accepting command input.
Eshell draws its prompt only there: the character right before
`eshell-last-output-end' carries the `prompt' field exactly while
input is pending, never in output or while a command still runs."
    (and eshell-last-output-end
         (>= (point-max) eshell-last-output-end)
         (> (point-max) (point-min))
         (eq (get-text-property
              (max (point-min)
                   (1- (marker-position eshell-last-output-end)))
              'field)
             'prompt)))

  (defun eshell--edit-read-line ()
    "Return the current command line in this eshell buffer.
Eshell delimits the pending input with the marker
`eshell-last-output-end', which rests right after the prompt
whenever command input is pending."
    (buffer-substring-no-properties
     eshell-last-output-end (point-max)))

  (defun eshell--edit-put-back (source text)
    "Place TEXT on the eshell prompt of SOURCE, without executing it.
The shell's pending input is deleted from the prompt onwards, so
the prompt is left with exactly the edits, ready to run with RET.
When the shell is no longer prompting (a command started meanwhile),
nothing is written and the edit is discarded."
    (if (not (with-current-buffer source (eshell--edit-prompting-p)))
        (message "shell edit: the shell is gone, discarding the edit")
      (with-current-buffer source
        (goto-char (point-max))
        (delete-region eshell-last-output-end (point-max))
        (when (> (length text) 0)
          (insert text))
        (goto-char (point-max)))))

  (defun eshell--edit-command-line ()
    "Edit the current eshell command line in a fresh buffer.
Like `vterm--edit-command-line' for vterm: C-c C-c puts the edited
text back on the prompt and C-c C-k leaves the command as it was;
nothing is executed."
    (interactive)
    (unless (eshell--edit-prompting-p)
      (user-error "A command is still running in this eshell buffer"))
    (shell--edit-buffer (current-buffer)
                        (eshell--edit-read-line)
                        #'eshell--edit-put-back))

  ;; The keymap is defined by esh-mode, which eshell itself loads
  ;; only when the first buffer is created: waiting for the `eshell'
  ;; feature is not enough.
  (with-eval-after-load 'esh-mode
    (define-key eshell-mode-map (kbd "C-x C-e") #'eshell--edit-command-line))
#+end_src

* Eshell
#+begin_quote
Eshell is a shell-like command interpreter implemented in Emacs
Lisp. It invokes no external processes except for those requested by
the user. It is intended to be an alternative to the IELM (see [[https://www.gnu.org/software/emacs/manual/html_mono/emacs.html#Lisp-Interaction][Lisp
Interaction]] in /The Emacs Editor/) REPL for Emacs and with an interface
similar to command shells such as bash, zsh, rc, or 4dos.
#+end_quote

Since =vterm= doesn't support Windows operating system, the next viable
choice for a command line interface is presicely *eshell.*

#+begin_src emacs-lisp
  (defun shell--popup-eshell ()

Like `shell--popup-vterm' for vterm: popup-window.el closes the window
when the shell is gone."
    (interactive)
    (funcall (make-repl-popup #'eshell)))

  (evil-define-key '(normal visual) 'global
    (kbd "SPC t e") 'shell--popup-eshell
    (kbd "SPC t E") 'eshell)
#+end_src

* Term, shell and ielm
Gnu term provides a terminal emulator buffer, shell a comint
wrapper for the system shell, and ielm an Emacs Lisp REPL. They
join the =SPC t= prefix like the shells: lowercase opens the buffer
in a popup window, uppercase selects it in the current window.
=ielm= spawns no process, so its popup window does not close by
itself; =term= and =shell= do, like the shells.

#+begin_src emacs-lisp
  ;; `term' takes the program to run as one mandatory argument in
  ;; Emacs 30 -- it is a native subr, arity \(1 . 1) -- so binding it
  ;; straight to a key fails at command execution with "Wrong number
  ;; of arguments".  This wrapper supplies the program, defaulting
  ;; like `term' itself and `projectile-run-term' do.
  (defun shell--term (&optional program)
    "Start `term' on PROGRAM, with the same default `term' prompts for.
Bound as =SPC t T=, it asks for the program, =SPC t t= takes the
default through `shell--popup-term'."
    (interactive
     (list (read-shell-command
            "Run program: "
            (or explicit-shell-file-name shell-file-name
                (getenv "ESHELL")))))
    (term (or program
              (or explicit-shell-file-name shell-file-name
                  (getenv "ESHELL")))))

  (defun shell--popup-term ()
    "Open term in a popup window at the bottom of the frame.
Like `shell--popup-vterm' for vterm: popup-window.el closes the
window when the shell is gone."
    (interactive)
    (funcall (make-repl-popup #'shell--term)))

  (defun shell--popup-ielm ()
    "Open ielm in a popup window at the bottom of the frame.
Like `shell--popup-eshell' for eshell.  Ielm runs no external
process, so the popup stays until the buffer is killed."
    (interactive)
    (funcall (make-repl-popup #'ielm)))

  (defun shell--popup-shell ()
    "Open shell in a popup window at the bottom of the frame.
Like `shell--popup-vterm' for vterm: popup-window.el closes the
window when the shell is gone."
    (interactive)
    (funcall (make-repl-popup #'shell)))

  (evil-define-key '(normal visual) 'global
    (kbd "SPC t s") 'shell--popup-shell
    (kbd "SPC t S") 'shell
    (kbd "SPC t t") 'shell--popup-term
    (kbd "SPC t T") 'shell--term
    (kbd "SPC t i") 'shell--popup-ielm
    (kbd "SPC t I") 'ielm)
#+end_src

* Term and shell editors
The =C-x C-e= editor reaches the two remaining shells too: a
=term= buffer and a =shell= buffer (and, through =comint=, any
comint REPL they happen to run).  The command line lands in its
own buffer -- in a fresh frame when Emacs is graphic -- with
=C-c C-c= putting the edit back on the prompt, ready to run with
=RET=, and =C-c C-k= (or plain =C-x k=) discarding it; nothing is
ever executed.

Where the pending input rests decides how the editor reads and
puts it back.  A comint buffer keeps it in the buffer itself,
from =process-mark= to the end -- the exact region
=comint-send-input= sends on =RET=, so the lines accumulated with
=M-RET= (=comint-accumulate=) are part of the edit -- and the
editor reads the line and pastes the edit back with plain buffer
edits: nothing is sent to the inferior.

#+begin_src emacs-lisp
  (defun comint--edit-input-start ()
    "Return the position where the pending input starts in this buffer.
The region `comint-send-input' sends on RET: the accumulated
lines of `comint-accumulate' and the plain typed-ahead input all
rest after `process-mark', which follows the end of the last
prompt."
    (process-mark (get-buffer-process (current-buffer))))

  (defun comint--edit-process-live-p ()
    "Return t when the shell process of this comint buffer is alive."
    (and (get-buffer-process (current-buffer))
         (process-live-p (get-buffer-process (current-buffer)))))

  (defun comint--edit-read-line ()
    "Return the current command line in this comint buffer.
Everything after `comint--edit-input-start' is what the buffer is
carrying for the next RET -- typed-ahead and accumulated input
included; the process output, prompt included, is everything
before it."
    (buffer-substring-no-properties
     (comint--edit-input-start) (point-max)))

  (defun comint--edit-put-back (source text)
    "Place TEXT on the shell prompt of SOURCE, without executing it.
The pending input is deleted from `process-mark' onwards and TEXT
takes its place, ready to run with RET; the `comint-accumulate'
state is reset as well, since the edit covers the accumulated
lines too.  When the shell process is no longer alive, nothing is
written and the edit is discarded."
    (if (not (with-current-buffer source
               (comint--edit-process-live-p)))
        (message "shell edit: the shell is gone, discarding the edit")
      (with-current-buffer source
        (let ((inhibit-read-only t))
          (goto-char (point-max))
          (delete-region (comint--edit-input-start) (point-max))
          (set-marker comint-accum-marker nil)
          (when (> (length text) 0)
            (insert text))
          (goto-char (point-max))))))

  (defun comint--edit-command-line ()
    "Edit the current comint command line in a fresh buffer.
Like `eshell--edit-command-line' for eshell, for any comint REPL:
M-x shell is the buffer the binding is bound for, but inferior
buffers based on comint get the same editor, since the pending
input is delimited the same way."
    (interactive)
    (unless (comint--edit-process-live-p)
      (user-error "No running shell in this comint buffer"))
    (shell--edit-buffer (current-buffer)
                        (comint--edit-read-line)
                        #'comint--edit-put-back))

  (with-eval-after-load 'comint
    (define-key comint-mode-map (kbd "C-x C-e") #'comint--edit-command-line))

  ;; The term editors, on the other hand, split on the term mode.  A
  ;; `term' shell enters char mode when it spawns: the buffer holds
  ;; the terminal screen alone, and the pty carries the truth -- the
  ;; editor goes through it, sending readline keystrokes, exactly
  ;; like the vterm one.  In line mode the pending input rests in
  ;; the buffer after the process mark, and the editor works like
  ;; the comint one: nothing is sent.

  (defun term--edit-read-between (beg end)
    "Return the screen text from BEG to END.
BEG and END sit at the two ends of the shell's logical command
line; the screen text between them is read through the lines the
terminal wrapped it into."
    (let (chunks)
      (save-excursion
        (goto-char beg)
        (while (< (point) end)
          (let ((stop (min (line-end-position) end)))
            (push (buffer-substring-no-properties (point) stop) chunks)
            (goto-char stop)
            (unless (eobp) (forward-char))))
        (apply #'concat (nreverse chunks)))))

  (defun term--edit-read-line ()
    "Return the shell's current command line in this term buffer.
In char mode readline's =C-e= and =C-a= are sent first: C-e parks
the terminal cursor -- which `process-mark' follows -- at the end
of the logical line and C-a at its start; the command line is the
screen text between the two, without any shell integration or
prompt detection.  The side effect is that the shell's cursor
ends at the start of its input line.  In line mode nothing is
sent to the pty: the pending input is the text between the
process mark and the end of the buffer."
    (let ((proc (get-buffer-process (current-buffer))))
      (if (term-in-char-mode)
          (progn
            (term-send-raw-string "\C-e")
            (when proc (accept-process-output proc 0.5))
            (let ((end (marker-position (process-mark proc))))
              (term-send-raw-string "\C-a")
              (when proc (accept-process-output proc 0.5))
              (term--edit-read-between
               (marker-position (process-mark proc)) end)))
        (buffer-substring-no-properties
         (process-mark proc) (point-max)))))

  (defun term--edit-put-back (source text)
    "Place TEXT on the term prompt of SOURCE, without executing it.
In char mode readline's =C-a= =C-k= discards the shell's current
input first, like vterm's editor does, TEXT is then sent verbatim,
and =C-l= redraws the line: the redraw rewrites the line's whole
wrapped width, which the terminal emulator needs when the edit
replaces a line of another length -- without it the screen and
the read that follows keep stale wrapped rows.  In line mode the
shell's pending input is deleted from the process mark onwards --
`comint--edit-put-back' style -- so the prompt is left with
exactly the edits, ready to run with RET."
    (if (not (with-current-buffer source
               (term-check-proc (current-buffer))))
        (message "shell edit: the shell is gone, discarding the edit")
      (with-current-buffer source
        (if (term-in-char-mode)
            (progn
              (term-send-raw-string "\C-a")
              (term-send-raw-string "\C-k")
              (when (> (length text) 0)
                (term-send-raw-string text))
              (term-send-raw-string "\C-l"))
          (let ((inhibit-read-only t)
                (proc (get-buffer-process (current-buffer))))
            (goto-char (point-max))
            (delete-region (process-mark proc) (point-max))
            (when (> (length text) 0)
              (insert text))
            (goto-char (point-max)))))))

  (defun term--edit-command-line ()
    "Edit the shell's current command line in a fresh buffer.
Like `vterm--edit-command-line' for vterm, mirroring readline's
`edit-and-execute-command': the command line of this term -- char
or line mode, whichever the buffer is in -- is copied into a
temporary buffer, shown in a new frame when Emacs is graphic.
There, C-c C-c puts the edited text back on the prompt and C-c C-k
discards it; nothing is executed."
    (interactive)
    (unless (term-check-proc (current-buffer))
      (user-error "No running shell in this term buffer"))
    (shell--edit-buffer (current-buffer)
                        (term--edit-read-line)
                        #'term--edit-put-back))

  (defun term--edit-send-raw-keys ()
    "Send the command's whole key sequence to the inferior's pty.
The C-x chords of `term-raw-map' that the editor's prefix map does
not rebind fall back on this one: `term-send-raw' cannot serve
there, because it sends only the last event, which would strip the
C-x off chords like C-x C-s."
    (interactive)
    (let ((keys (this-command-keys))
          (chars-only t))
      (dotimes (i (length keys) chars-only)
        (unless (characterp (aref keys i))
          (setq chars-only nil)))
      (when chars-only
        (term-send-raw-string keys))))

  (defvar term--edit-raw-ctl-x-map
    (let ((map (make-sparse-keymap)))
      ;; The editor is the one chord the editor itself rebinds; every
      ;; other C-x chord keeps reaching the inferior's pty through the
      ;; default binding above, so the raw C-x semantics survive.
      (define-key map "\C-e" #'term--edit-command-line)
      (define-key map [t] #'term--edit-send-raw-keys)
      map))

  (with-eval-after-load 'term
    (define-key term-mode-map (kbd "C-x C-e") #'term--edit-command-line)
    ;; Char mode intercepts every single key, C-x included, so the
    ;; prefix is rebuilt here instead of shadowed wholesale: a plain
    ;; C-x C-e binding would leave every other C-x chord undefined.
    (define-key term-raw-map "\C-x" term--edit-raw-ctl-x-map))
#+end_src
