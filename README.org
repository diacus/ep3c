#+TITLE: Emacs Pretty Personal Portable Configuration
#+AUTHOR: Diacus Mágnuz
#+STARTUP: logdrawer

EP3C (Emacs Pretty Personal Portable Configuration) is a modular,
batteries-included Emacs configuration. It uses =use-package= for
declarative package management and organizes settings into independent
modules written in Org mode.

Modules are loaded via =org-babel-load-file= and can be enabled or
disabled through Emacs' customization interface.

See the settings [[file:src/modules/*.org][here]].

* Installation
To install the settings, load =src/install.el= and call
=(ep3c--setup)=. Follow these steps:

1. Clone the reepository and open this =README.org= file.
2. Jump to the installer source code block: =C-s installer-script C-s
   RET=
3. Execute the installer: =C-c C-c=
4. When promped /Evaluate this emacs-lisp code block... (yes or no)/
   reply *yes* and hit =RET=

#+NAME: installer-script
#+begin_src emacs-lisp :results none
  (load-file (file-name-concat default-directory "src" "install.el"))
  (ep3c--setup)
#+end_src

When installation is done, =*Customize Option: Ep3c Modules*= buffer
will display, you can select the modules you want to load from there.

Once the Ep3c Modules option is ready for you, restart Emacs the way
you usually do.

* Remove configuration
To get rid of everything just delete =user-emacs-directory=
#+name: remove-everything
#+begin_src emacs-lisp :results none
  (delete-directory user-emacs-directory t t)
#+end_src

To delete the settings but keep the rest, only delete the =init.el=
and =core.el= files and the =modules= folder.

#+name: delete-settings-only
#+begin_src emacs-lisp :results none
  (delete-file (file-name-concat user-emacs-directory "init.el"))
  (delete-file (file-name-concat user-emacs-directory "core.el"))
  (delete-directory (file-name-concat user-emacs-directory "modules") t)
#+end_src

* Testing
The test suite is written with ERT and runs without a graphical
session. To check the repository, from the project root run:

#+name: run-tests
#+begin_src sh :results none
  emacs -Q --batch -l test/run.el
#+end_src

If projectile is available, use =M-x projectile-test-project RET= then
type the test command and hit =RET.= The test results will be available
in the =*compilation*= buffer.

The command exits with status 0 when every test passes and 1
otherwise, which makes it usable as a CI entry point.

The suite covers the modules under =src/modules/= and the installer:

- every module tangles into balanced Emacs Lisp, using the same
  tangling semantics =org-babel-load-file= applies at startup;
- every module carries the =#+TITLE=, =#+AUTHOR= and =#+STARTUP:
  overview= properties;
- the installer copies =init.el=, =core.el= and all modules into a
  temporary =user-emacs-directory=, and unknown or legacy modules
  are validated correctly.

* Keybindings
** Leader Key
Most keybindings hang from a leader key.  With the evil module it is
=ep3c-evil-leader= (default =SPC=); without it
=ep3c-non-evil-leader= (default =C-c=), and =ep3c-define-key=
re-points the whole tree -- the modules write their keys
leader-relative either way.  Both are customization variables: set
them with =M-x customize-variable= or in =custom.el=.  =C-c= is the
namespace the manual reserves for the user, so in any buffer whose
major mode binds =C-c C-x= chords the local mode wins over the
leader; =which-key= shows the full tree under either leader.

The tables below write =LEADER x y=: read as =SPC x y= with evil or
=C-c x y= without it (or whatever key you customized the regime's
leader to).  Language modules may override leaves of the =LEADER p=
run subtree inside their own major modes: =LEADER p r r= is the
reserved leaf for "the language's REPL" (haskell registers
=haskell-interactive-bring= there), and each override is bounded to
that language's buffers only.

*** Tree (=LEADER e=)
The treemacs file-tree commands hang from the leader (=C-c e …= in
the non-evil regime): the upstream-recommended =C-x t= chords
collide with tab-bar's =C-x t= prefix on Emacs 29+, replacing its
whole tree.  They are also bound in treemacs' own evil state, so
=LEADER e e= closes the tree when the cursor is already inside the
treemacs window.

| =LEADER e e= | treemacs                      |
| =LEADER e 1= | treemacs-delete-other-windows |
| =LEADER e d= | treemacs-select-directory     |
| =LEADER e b= | treemacs-bookmark             |
| =LEADER e f= | treemacs-find-file            |
| =LEADER e g= | treemacs-find-tag             |

*** Docker (=LEADER D=)
Lives on the leader's uppercase =D= slot, inside the which-key
leader tree; uppercase to stay clear of the =LEADER d= dap subtree.
Bound through =ep3c-define-key=: a plain =C-c D= =global-map=
binding would race the leader map for the =C-c= prefix in the
non-evil regime and lose, load-order dependent.

| =LEADER D=   | docker  |
